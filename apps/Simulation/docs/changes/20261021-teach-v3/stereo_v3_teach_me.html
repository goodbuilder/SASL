0.1타깃 좌표는 어떤 뜻인가요?

왜 필요한가요선정 코드 1645–1649행은 다섯 위치에 카메라 자세 불확실성을 전파합니다. 타깃 위치는 실제 V0 위치오차가 아닙니다.

0.2평균과 중앙값은 어디에 쓰이나요?

무엇인가요평균은 합을 개수로 나눕니다. 중앙값은 값을 정렬한 뒤 가운데를 고릅니다. P2 선정은 이 두 연산을 순서대로 사용합니다.
왜 필요한가요각 교정 실행×방법에서 타깃 5점의 σ를 평균합니다. 경로 하나에서는 5실행×3방법의 평균 15개를 정렬해 8번째를 선정 점수로 씁니다. 선정 코드 1677–1700행에 두 단계가 있습니다.
예제 숫자로3.058051158 m ÷ 5 = 0.611610232 m가 P2-R01/A의 타깃 평균입니다. P2의 15개 평균 중 정렬된 8번째는 0.611701449 m입니다.

0.3case와 비행은 왜 다른가요?

무엇인가요run은 저장된 시뮬레이션 비행 하나입니다. MC trial은 같은 궤적에 대해 합성 입력을 바꿔 수행한 오프라인 계산 사례입니다.
왜 필요한가요16_실행별V0의 한 행은 교정 run과 대응 V0 run 안에서 7 yaw × 100 MC = 700 case의 지표를 평균합니다. case 수를 독립 비행 표본 수로 쓰면 안 됩니다.
예제 숫자로G0-P2-R01/A/all_data의 평가 CSV에는 Y0–Y6 각각 trial 0–99가 있어 700행입니다. 대응 V0 ID는 G0-V0-R01입니다.
직접 해보기같은 경로·방법·범위에서 5개 대응 실행을 합치면 case는 몇 개인가요?
정답 보기

5 × 7 × 100 = 3,500 case입니다. 물리 비행 3,500회라는 뜻은 아닙니다.

계산에 등장하는 방법을 구분하세요

방법 이름은 동결 분석 방법론과 XLSX 11_방법계약의 정의를 따릅니다.

이름입력과 추정이 페이지에서의 역할
A좌우 카메라 자세를 각각 추정하며 noisy 드론 RTK를 사용선정 점수와 V0 예제의 방법
B좌우가 영상 pair별 3D 점을 공유하고 드론 RTK를 사용P2/P0 대응 비교의 다른 방법
C공유 3D 점을 영상으로 추정하며 드론 RTK를 추정기에 넣지 않음선정 점수의 15개 값에는 포함됨
RPY_IMU카메라 roll·pitch·yaw를 추정하고 IMU roll/pitch prior를 사용이 페이지의 선정·V0 예제 조건
YAW_ONLY같은 IMU 평균 roll/pitch를 고정하고 yaw만 추정XLSX 14_P95짝비교의 상대 조건
입력 경계: C도 공통 영상 표본을 고를 때는 드론 RTK 시간 구간이 있는 pair를 사용합니다. 합성 센서 생성기는 참 자세를 읽을 수 있지만, 주 A/B/C 추정기는 GT 위치를 입력받지 않습니다. V0 GT는 동결 자세의 위치 평가에 사용합니다. Huber 손실은 영상 잔차에만 적용되며 RTK·IMU 항은 이차 Gaussian 비용입니다.

1P2는 어떤 순서로 선택됐나요?

선정 코드 1651–1700행은 V0 결과를 읽기 전에 G0의 Y0, all_data, trial 0, RPY_IMU 중 수렴한 A/B/C를 사용합니다. 다섯 타깃의 σ를 실행×방법별로 평균하고, 경로마다 15개 평균의 중앙값을 계산합니다. 과정은 위 0.2 흐름 그림과 같습니다.

15개를 정렬하면 8번째는 0.611701449 m입니다. P4 점수는 0.611774381 m이므로 P4−P2=0.000072931 m≈0.073 mm입니다. 동결 규칙은 P2를 골랐습니다. 이는 V0에서 P2가 가장 낮은 실측 오차를 냈다는 뜻이 아닙니다.

선정 안정성: 15_선정민감도에서 경로마다 같은 반복번호의 A/B/C 값을 제외하면 P2가 2회, P4가 3회 1위입니다. 이 분석은 원래 동결 선택을 바꾸지 않습니다.

2V0 실행별 평균은 어떻게 읽나요?

동결된 카메라 자세로 V0 픽셀을 삼각측량하고, 평가기에서 GT와 비교합니다. 16_실행별V0는 같은 반복번호의 교정 run과 V0 run을 묶습니다. 각 yaw×MC case에서 이미 계산된 3D RMSE 700개를 평균합니다. 전체 프레임을 하나로 합쳐 다시 계산한 RMSE와는 다른 집계입니다. 위 0.3 그림에서 700의 뜻을 확인하세요.

G0-P0-R01 / A / all_data: 777.719994904 m ÷ 700 = 1.111028564 m
G0-P2-R01 / A / all_data: 783.649345680 m ÷ 700 = 1.119499065 m
P2 − P0 = +0.008470501 m

양수이므로 저장된 R01 조건에서는 P2의 case 평균 오차가 더 큽니다. 다른 네 실행의 대응 차이는 16_실행별V0!A22:I41에 있습니다. `all_data`의 A/B는 다섯 실행 모두 P2가 높지만, `matched_200`의 평균 방향은 다릅니다. 독립 비행의 신뢰구간으로 해석하지 마세요.

3추종 P95가 두 값인 이유는?

기록값 생산 코드 15–34행은 비행 상태 행에 저장된 GT와 참조 위치를 비교하고 GT 시각차가 40 ms를 넘으면 제외합니다. 재정렬값 생산 코드 90–119행은 연구 구간 제어 시각에 원시 GT를 다시 보간합니다. 둘 다 world ENU의 GT−참조 3D 거리와 type-7 보간 P95를 쓰지만 입력 GT 위치가 다를 수 있습니다.

17_추종P95출처의 G0-P0-R01/a02 기록값은 3.913999 m, 재정렬값은 3.889329 m입니다. 차이는 약 0.024670 m입니다. 원본 V0 8개의 재정렬 tracking은 동결 전 공개되지 않아 빈칸입니다. 빈칸을 0 m로 읽지 마세요.

자주 틀리는 지점

  • world ENU의 U는 위쪽 양수입니다. PX4 NED의 D와 바꾸지 마세요.
  • 경로 후보 JSON의 mean_sigma 필드명만 보고 최종 점수를 전체 평균으로 읽지 마세요.
  • 타깃 5점 보조 p95는 두 번째로 큰 값입니다. 일반적인 95백분위라고 인용하지 마세요.
  • 700 case는 7 yaw×100 MC입니다. 비행 700회가 아닙니다.
  • `all_data`의 P0 우위를 `matched_200`까지 확대하지 마세요.
  • 추종 1 m는 경고선입니다. 자동 폐기나 정확도 합격선이 아닙니다.
확인하지 않은 것: 이번 설명을 위해 전체 분석 solver나 SITL을 재실행하지 않았습니다. PX4 난수·비행 반복의 독립성, 모든 case에서 양 자세 변형의 동일 유효 frame ID도 검증하지 않았습니다.
