새로 추가한 선정 계산·QC·P95 짝비교의 수치 오류는 확인되지 않았습니다. 상급자가 XLSX만 읽을 때 P2의 의미, 보조 “P95”, truth 사용 범위를 잘못 해석할 수 있는 문구는 수정해야 합니다.

주요 수정 의견

주요 1“타깃 P95 σ”는 일반적인 95백분위가 아님

선정 함수는 5개 타깃 σ를 오름차순으로 정렬해 int(0.95×(5−1))=3번째 인덱스, 즉 5개 중 두 번째 큰 값을 사용합니다. XLSX는 같은 연산을 LARGE(5점,2)로 정확히 재현하지만 “P95”라는 이름은 보간 95백분위로 읽힙니다.

근거: XLSX 12_P2선정추적!A17,E19:E94,F9:G14, 06_리뷰판정!E26:E31; analyze_campaign.py 1677–1695행.

수정: 이 열을 “5개 타깃 중 두 번째 큰 예측 σ의 중앙값”으로 이름 붙이거나, 95백분위를 쓰려면 정의를 명시하고 별도로 재계산하세요. 이 보조값은 P2 선택 점수가 아닙니다.

주요 2P2 중앙값은 이 자료에서 A 방법이 결정함

경로별 점수는 A/B/C 각 5개, 총 15개 타깃 평균 σ의 중앙값입니다. 원자료를 다시 묶으면 P0–P4 모두 결합 중앙값이 A의 중앙값과 정확히 같습니다. P2의 결합 점수는 0.611701449 m, P4는 0.611774381 m로 차이가 약 0.073 mm입니다. B와 C 각각의 중앙값은 P4가 P2보다 낮습니다.

근거: XLSX 12_P2선정추적!A3,C10:C14,D20:D94; path_selection.json.

수정: 선정 표 옆에 방법별 점수와 “이번 자료에서는 A 값이 결합 중앙값을 결정했다”는 주석을 추가하세요. P2는 사전 규칙의 선정 경로로만 설명하고, A/B/C 전반의 최적 경로라고 주장하지 마세요.

주요 3GT 사용 경계를 단계별로 분리해야 함

XLSX 11_방법계약!B15의 “GT는 평가기에만 사용”은 V0 위치 GT의 평가 입력을 설명할 때는 맞지만, 전체 파이프라인 설명으로 읽으면 넓습니다. 합성 RTK·IMU 생성기는 참 카메라 자세 등을 사용할 수 있고, A/B/C 추정기는 truth를 직접 입력받지 않습니다. YAW_IDEAL/ORACLE은 별도 truth 보조 진단입니다.

근거: XLSX 11_방법계약!B11,B15; 작업지시서 299행; 분석 방법론 7–14, 27–29행.

수정: “합성 관측 생성의 truth”, “A/B/C 추정기 입력”, “V0 위치 GT 평가”를 각각 한 문장으로 설명하세요.

중간 4C 방법의 표본 선택은 드론 RTK 가용성에 의존함

C 추정기에 드론 RTK 위치를 넣지 않는 설명은 맞습니다. 다만 all_data 공통 pair mask는 10 Hz 드론 RTK 시각 bracket이 있는 영상 pair를 요구하고 C도 이 표본을 사용합니다. 11_방법계약!B14의 “유효 pair”만으로는 이 조건이 드러나지 않습니다.

근거: XLSX 11_방법계약!B8,B14; 교정 설명 213–215행.

수정: C의 추정 입력에는 RTK가 없지만 공통 표본 선정에는 RTK 시간 bracket이 필요하다고 명시하세요. RTK 수집 자체가 없는 조건을 검증한 것으로 확대하지 마세요.

근거: XLSX 00_요약!B13:C14, 05_그래프!A224:H231, 14_P95짝비교; analysis_freeze.json.

수정: “V0 지표 산출 완료·정확도 합격 판정 없음”과 “3D RMSE 개선 비율”로 범위를 표시하세요. P95 개선은 새 14번 시트의 별도 지표로 안내하세요.
