SASL 소스에 맞춘 실행 연결 규격 - v1.2 / 2026-10-13

분석한 저장소: https://github.com/goodbuilder/SASL
브랜치: Final
커밋: 0d83e0a2f7fe45c2f6c34f480bfb92a34fb7fd59
프로그램 폴더: apps/Simulation (SASL은 저장소 이름)
이 문서는 소스 분석 결과다. 학생 PC의 설치 상태, 실제 Gazebo 실행, 추정기 성능은 검증하지 않았다.
학생의 현재 커밋이 다르면 변경사항을 비교해 연결표를 갱신한다. 기존 미커밋 변경을 지우거나 특정 커밋으로 강제 reset하지 않는다.

1. 실제 구조와 재사용 범위 (아래 경로는 저장소 루트 기준)
- config: apps/Simulation/config/simulation.env. 공통 설정을 읽고 SIM_SCENARIO_CONFIG로 시나리오를 덮어쓴다.
  scripts/load_sim_config.sh 및 각 runner가 보존하는 환경변수 목록을 확인한다. 셸에서 설정한 값이 실제 launch까지 전달되었는지 effective_config로 검증한다.
- 실행 기반: apps/Simulation/run_operator_view.sh. Gazebo/ROS/PX4/카메라/YOLO/기록 연결을 재사용한다.
- 기존 자동 임무: apps/Simulation/run_auto.sh. FOV 제약 waypoint 생성과 run_mission.sh를 사용하고 Full recorder도 실행한다.
  README 일부의 기록 여부 설명보다 실제 스크립트가 우선이다. FOV guard가 비행을 바꾸는 기존 경로 생성기를 논문 경로에 자동 적용하지 않는다.
- 기존 sweep: apps/Simulation/run_auto_attitude_sweep.sh. 실행/정리/재개 패턴과 메타데이터를 참고하되 39회 전용 manifest driver를 연결한다.
  현재 기본은 center/zigzag 각각 기준 1개+3축×3크기(.2,.5,1.0) = 20조건이다. 과거 run11-final의 122조건과 현재 기본값은 다르다.
- 비행: apps/Simulation/run_px4_waypoint_mission.sh -> scripts/px4_waypoint_mission.py.
  기존 파일은 north,east,altitude[,hold_s] CSV이며 parse_xy_alt가 NED Down=-altitude로 바꾼다.
  이름이 AGL이어도 실제 입력은 LOCAL_NED 원점에 대한 고도다. 지면 절대고도로 오해하지 않는다.
  각 waypoint에서 remaining 기반 감속 및 수평/수직 별도 ramp를 다시 시작한다. hold=0 또는 촘촘한 CSV만으로 50Hz 연속 경로가 되지 않는다.
- 물리 카메라: apps/Simulation/stereo_ground_sim/launch/stereo_ground_sim.launch.py.
  _generate_world_sdf의 광학 각도와 PX4 body 자세는 독립이다. 광심은 고정하고 optical pose를 변경하는 기존 구조를 사용한다.
- 좌표/계산: apps/Simulation/stereo_ground_sim/stereo_ground_sim/coordinate_frames.py,
  camera_pose_coordinator.py, pose_conversion_adapter.py, stereo_distance_node.py 및 stereo_measurement_pipeline.py.
- 기록: 같은 패키지의 operator_recorder.py, research_recording.py, research_record_fields.py, gazebo_ground_truth_adapter.py.
  pair_records JSONL과 terminal 상태/메타데이터를 재사용할 수 있으나 전체 원본 프레임 보존을 별도로 보장해야 한다.
- 기존 보정: scripts/rtk_stereo_calibration_pipeline.py에는 정합·잔차 보정 등이 있고,
  패키지의 correction_qualification.py에는 dual_camera_wahba_so3/shared_wahba_so3가 있다.
  Wahba 초기화·순수 기하 도구는 재사용 후보지만 finite IMU prior의 A/B/C 전체 구현으로 간주하지 않는다.
  기존 qualification은 25개 자세 profile/각18개 교정 case를 전제한다. 새39회에 기존 완료 판정을 그대로 적용하지 않는다.

2. 구현 후 실행해야 할 항목
아래 새 이름은 권장 설계명이며 현재 저장소에 존재하는 명령으로 간주하면 안 된다.
(a) scripts/run_paper1_campaign.py: 39개 manifest, G0/G1별 scenario, run/attempt 격리, resume, 매회 QC, 정상 종료 후 기록 flush.
(b) scripts/px4_reference_trajectory_mission.py: 05_generate_reference.py가 만든 시간별 ENU 위치/속도 추종.
    기존 offboard 통신과 arming/착륙 수명주기를 활용하되 연속 시간 참조/피드백을 구현한다.
    /clock로 science elapsed를 계산하고 reset/일시정지 시 epoch를 구분한다. host monotonic 경과를 비행 참조 시간으로 그대로 쓰지 않는다.
    송신 cadence, simulation-time cadence, real-time factor를 함께 측정한다. reference 50Hz 유지 여부를 확인한다.
    고정 heading 180deg 명령의 type mask와 단위를 검증한다. 실제 roll/pitch는 동역학 결과로 둔다.
    PX4 속도/가속도/고도 제한을 점검하고 공통값으로 동결한다. 경로별로 제어 gains를 맞추지 않는다.
    안정화 판정/5초 hold, science_start/end, 종료 hold는 별도 event로 남긴다.
(c) raw recorder + schema adapter: 원본 image, clock, authoritative GT, 카메라 pose, per-frame detection, 상태/phase를 저장한다.
(d) scripts/paper1_offline_calibration.py 또는 동등 모듈: 센서 관측 생성기, 추정기 입력 분리, RPY_IMU/YAW_ONLY A/B/C, V0 평가.
    데이터 수집 완료와 추정기 구현 완료를 따로 보고한다. 원시 기록은 추정기 완성을 기다리지 않고 검증·수집할 수 있다.
    C는 yaw 관측성이 부족할 수 있다. Jacobian의 singular values/rank, IMU prior 의존성 및 다중 초기값 결과를 보고한다.
    C를 강제로 성공시키기 위해 GT, 실제 경로, yaw 참값, 임의 yaw prior를 추가하지 않는다.
    기존 Wahba의 rank3 gate와 새 문제의 관측성 판정을 구분하고 기존 fixture 검사를 임의로 약화하지 않는다.

3. 핵심 설정과 좌표 계약
- CAMERA_CLIP_FAR_M: 현재 env 500.0 -> 본 캠페인 모두 1000.0.
  launch 코드의 다른 기본값보다 env가 우선한다. V0 시작 수평거리600m, 고도218.382m이며 카메라 깊이는 약638m다.
  500m clipping은 이 구간을 자른다. 1000m는 렌더링 한계 변경이며 K/HFOV/해상도는 유지한다.
- G0 CAM_L/R_OPTICAL_ROLL_DEG=0, PITCH_DEG=20, YAW_DEG=0.
- G1 같은 roll/pitch에 CAM_L_OPTICAL_YAW_DEG=+0.5, CAM_R_OPTICAL_YAW_DEG=-0.5.
- COMMON_OPTICAL_*_ERROR_DEG와 RELATIVE_OPTICAL_*_ERROR_DEG는 모두 0.
- 양 군 모두 camera PX4 attitude 설정은 roll=0,pitch=20,yaw=0으로 고정해 광학 오차와 분리한다.
  이것이 main offline IMU/RTK 모의 관측을 대신하지는 않는다. 별도 noisy 관측을 생성해 A/B/C에 제공한다.
- 소스 nominal_camera_poses는 수평 카메라다. 여기에 apply_optical_rpy_error(phi,20deg+theta,psi)를 적용하면
  문서의 Rz_world(-psi) @ R0 @ Rx(theta) @ Rz(phi)와 일치한다.
  따라서 이 launch 조합의 G1 yaw 값은 위 방위각과 일치한다. 이미 20deg 기울인 자세에 local yaw를 다시 적용하는 방식은 다르다.
  quaternion과 회전행렬로 실제 카메라 광축을 다시 확인한다. 설정 텍스트만으로 확인을 끝내지 않는다.
- 현재 공개 baseline_center_frd는 LEVEL nominal pose에서 만든 고정 frame이다.
  기본 rig의 world ENU (x,y,z) -> FRD (F,R,D)=(y,x,0.1-z); 역변환 (x,y,z)=(R,F,0.1-D).
  카메라 고각20도/G1 yaw에 맞춰 public frame을 임의로 회전시키지 않는다. 실제 origin/matrix를 기록하고 변환한다.
- PX4 LOCAL_NED는 world와 원점이 다를 수 있다. 원점이 world (xh,yh,zh)이고 축 정렬을 확인한 경우에만
  p_NED=(y-yh,x-xh,-(z-zh)), v_NED=(vy,vx,-vz)를 사용한다. heading 정렬도 실제 확인한다.
  PX4 q는 body FRD->Earth NED wxyz; optical-to-world q는 RDF->ENU xyzw. 순서만 바꾸는 것으로 frame 변환이 되지 않는다.
- 현재 vehicle_reference_link는 base_link 원점에 offset0인 프로젝트 기준점이다.
  이를 GNSS 안테나 중심이라고 부르지 않는다. 실제 model의 기준점/크기/안테나 lever arm을 확인해 기록한다.
  본 논문의 synthetic RTK는 명시한 동일 기준점 관측으로 생성한다.

4. 기록 계약과 기존 필드 연결
최소 raw bag 토픽:
  /clock
  /left_camera/image  /right_camera/image
  /left_camera/camera_info  /right_camera/camera_info
  /simulation/ground_truth/vehicle_reference_link
  /simulation/camera_pose_diagnostics/left  /simulation/camera_pose_diagnostics/right
추가로 비행 상태, phase 이벤트, 참조, per-frame bbox/미검출, PX4 시간 대응 및 카메라 센서 관측을 저장한다.
실제 토픽 이름·타입·QoS는 ros2 topic list/info로 확인한다. 모델별 Gazebo truth 토픽을 고정된 옛 모델명으로 연결하지 않는다.
기존 operator_recorder --mode debug의 bag 목록에는 raw image가 있지만 /clock과 위 vehicle_reference_link 토픽이 없다.
그 목록을 확장하거나 명시적 rosbag 기록기를 추가한다. full 모드 mp4v detection_image는 lossless 원본이 아니다.
pair_records만으로 미매칭 원본 프레임이 모두 남는다고 가정하지 않는다. image index와 검출 로그를 frame 단위로 대조한다.
pair_records left/right_observation_timestamp_ns -> 노출 이미지 시각; simulation_timestamp_ns -> pair midpoint.
gt_world_enu_* -> world ENU; operational_* 또는 diagnostic midpoint_* -> 각 schema의 FRD 계약을 확인 후 변환.
기존 sync_valid/sample_valid는 운영 pose 품질까지 포함하므로 이 플래그만으로 신규 raw 데이터를 탈락시키지 않는다.
paper1_qc 상태를 별도로 만들고 제외/실패 이유를 보존한다. correction_source=gazebo_observed_optical_pose는 ORACLE이다.
GT PoseStamped에 속도가 없으면 Gazebo 참 velocity를 별도 연결하거나 명시된 차분법/시각으로 derived velocity를 만든다.
PX4 추정 local_position을 Gazebo 참속도라고 이름 붙이지 않는다.
GT 최소50Hz와 보간 간격<=0.04s, stereo nominal skew<=1ms를 실제 측정한다. 최근값 반복을 샘플 증가로 세지 않는다.
카메라/YOLO 20Hz는 요청값이다. 실제 고유 frame rate, 탐지 시도율과 검출 성공률은 각각 기록한다.
원본 RGB 1280x720, 좌우20Hz라면 무압축 약111MB/s다. 준비/복귀 포함 실측 용량으로 디스크를 산정한다.
인프라 FPS 미달을 숨기거나 규격을 자동 완화하지 않는다. 공통 실행 설정을 조정 후 동결하고, 변경 전 attempt는 보존한다.

5. 센서오차 및 기존 실행과의 차이
현재 PX4 GPSsim fix/eph/epv는 cm급 RTK가 아니다. 메타데이터만 RTK라고 바꾸지 않는다.
main 카메라 RTK sigma_xyz=(.02,.02,.04)m, IMU roll/pitch sigma=.02deg,
드론 synthetic RTK 10Hz sigma_xyz=(.02,.02,.04)m는 별도 모의 관측이다.
같은 trial에서 카메라 고정 측정오차를 경로/방법/교정/V0에 공유한다. truth producer와 evaluator 외에는 truth 접근을 차단한다.
raw bbox 중심 보정/observation fusion/disparity-residual profile은 main에 적용하지 않는다.
run_operator_view.sh에 존재하는 --no-bbox-adjustment, --no-observation-fusion, --no-disparity-residual,
--no-disparity-residual-feature-selector를 사용하거나 동등한 effective 설정을 확인한다.
현재 SWEEP_SEED는 조건 순서 섞기에 쓰인다. seed별 sensor/dynamics 난수화가 자동 보장되지 않는다.
요청 seed와 모듈별 적용값/적용 여부를 저장하고 완전히 같은 반복은 중복 가능성으로 보고한다.

6. 학생 PC 실행 순서
단계1: 기존 데이터/수정사항 보존. 저장소 루트에서 아래 읽기·점검 명령 수행 후 결과 저장.
  git branch --show-current
  git rev-parse HEAD
  git status --short
  bash tools/check_operator_runtime.sh --execution
  bash apps/Simulation/run_operator_view.sh --help
ROS overlay가 없으면 기존 tools/bootstrap_ros_workspace.sh의 사용법/필요성을 확인해 복구한다.
PX4 v1.17.0, ROS/Gazebo, GPU/CUDA, torch/ultralytics, 가중치 실제 상태를 기록한다. 이유 없는 최신화는 하지 않는다.
단계2: 패키지에서 python3 05_generate_reference.py --output-dir ./reference_generated 수행.
단계3: 2절의 실행기·연속 제어·기록을 연결하고 unit/geometry/recording 검사 및 짧은 SITL 기록 시험.
단계4: 코드·설정·모델·가중치·시드 정책을 동결. G0-P0-R01, G0-P4-R01, G0-V0-R01, G1-P4-R01 점검.
이 네 슬롯이 동결된 최종 규격을 충족하면39회에 포함한다. V0에서는 가시성·기록·제어만 점검하고 측위 RMSE는 열지 않는다.
단계5: 나머지 manifest 순서를 직렬 실행. 각 회 준비 -> 기록 준비확인 -> 접근시작점 안정화 -> science -> 종료 hold -> 종료/flush -> QC -> 상태표 갱신.
기존 default mission/controller와 새 controller가 동시에 offboard 명령을 보내지 않도록 단일 소유자를 확인한다.
준비 이륙/진입에서는 동역학을 유지하고, 자동 target teleport/static 연구 모드는 끈다.
단계6: 캡처39슬롯 및 실패기록 인계. 추정기 구현 후 G0개발로 고정한 알고리즘/선정 규칙에 V0 최종평가.
본 실행의 실제 명령은 구현 후 --help/짧은 실행으로 검증해 학생 README에 제공한다.
이 문서는 존재하지 않는 39회 runner의 CLI를 이미 사용 가능한 것처럼 제시하지 않는다.

7. 재사용 판단
39개 ID/seed/경로와 RPY_IMU 주 교정 범위는 v1.1과 동일하다. 새 조건 추가는0개다.
그러나 현재 기본값으로 돌린20조건, 과거122조건, waypoint stop-go 비행은 신규39회와 동일하지 않다.
기존 신규39회 기록이라도 실제 clip/가시성, 연속 경로, 원본 영상/시각/GT/카메라 pose를 조건별 확인한 후만 재사용한다.
불충족 슬롯은 같은 run_id의 새 attempt로 수행한다. clip 설정 등이 다른 기록을 동등성 입증 없이 하나로 합치지 않는다.
추정 정확도가 낮거나 탐지가 실패했다는 이유로 재실행하지 않는다. 구현/설정 오류와 실제 성능 실패를 구분한다.

8. 완료 보고
source diff와 실제 명령, configuration hash, 39슬롯 상태표, 원본 bag/영상, schema_mapping,
frame/clock/GT 대조 QC, seed 적용 결과, 모든 attempt 및 protocol deviation을 전달한다.
status는 데이터 수집/알고리즘 구현/최종평가를 각각 표시한다. SCIE 게재 가능성을 실행 성공으로 판정하지 않는다.
