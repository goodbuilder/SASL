1. 한눈에 보기

목표는 시뮬레이터에서 스테레오 카메라 자세 교정과 비행 경로의 위치 측정 성능을 조사할 수 있도록, 규격에 맞는 원시 데이터를 모으고 재처리·평가가 가능한 실행 및 기록 체계를 갖추는 것입니다.

기존 저장소 조사→경로·좌표 검증→제어·기록 연결→짧은 SITL 점검→설정 동결→39개 비행→오프라인 교정·평가
물리 시뮬레이션계획된 영상 데이터 수집 슬롯은 39개입니다. 준비·재시도 attempt는 추가될 수 있지만, 계획 조건 자체는 늘리지 않습니다.
오프라인 계산각 기록을 여러 알고리즘·자세 조건·센서 오차 trial로 분석합니다. Monte Carlo 100회는 비행 100회를 추가한다는 뜻이 아닙니다.
주 교정법카메라 위치는 RTK 측정 좌표에 고정하고, 두 카메라의 roll·pitch·yaw를 유한한 IMU 사전정보와 영상/RTK 관측으로 추정합니다.
데이터 원칙원본 영상·시각·정답 위치와 파생 센서 관측·교정 결과를 분리합니다. 기록이 온전한 성능 실패도 결과로 보존합니다.
핵심 구분: 39개는 서로 다른 계획 비행 슬롯 수, 각 슬롯의 반복 수는 manifest에 적힌 비행 반복, 100회는 오프라인 Monte Carlo trial 수입니다. 이미지 프레임 수를 독립 비행 반복 수로 세지 않습니다.

배치점 값의 출처가 불완전합니다. 동반 캠페인 워크북의 Vehicle.spawn_east/north/up_m은 (0, 415, 6)m로 고정돼 있습니다. 하지만 이 워크북의 출처 칸은 03_experiment_spec.json을 가리키고, 현재 JSON에는 spawn 좌표나 Entry.entry_timeout_s 값이 없습니다. 따라서 워크북에 적힌 값은 현재 입력값으로 읽되, 415m/6m를 정한 근거나 규격 작성자의 의도로 설명하지 않습니다. 새 캠페인 전에 출처와 근거를 규격에 연결해야 합니다.

3. 계획된 39회는 어떻게 구성되나

실행 ID에서 G는 카메라 구성 그룹, P와 V는 비행 경로 식별자, R은 반복 번호를 나타냅니다. 공식 manifest 필드명과 각 ID의 뜻은 다음과 같습니다.

G / P / V 표기를 풀어 읽기

표기와 manifest 필드풀어쓴 역할구체적인 뜻
G=Group · G0 / rig_group명목 카메라 구성 그룹 (Nominal camera configuration group)좌·우 카메라 optical yaw가 모두 0°. roll=0°, 명목 pitch=20°.
G=Group · G1 / rig_group좌우 yaw 차등 카메라 구성 그룹 (Differential-yaw camera configuration group)G0와 roll/pitch는 같고, 왼쪽 yaw=+0.5°, 오른쪽 yaw=−0.5°.
P=Path · P0–P4 / path_id개발·교정 비행 경로 식별자 (Development/calibration path IDs)P0 직선, P1 낮은 활형(A=3m), P2 큰 활형(A=6m), P3 낮은 단일 S자(A=3m), P4 큰 단일 S자(A=6m). 모두 D=400→300m.
V의 공식 풀이는 미정 · V0 / path_id고정 최종 평가 경로 (Fixed final-evaluation path)manifest의 role=final_evaluation에 따른 직선 D=600→400m입니다. V는 VALID 상태나 “Valid”의 약자가 아닙니다. 규격에 V의 영단어 풀이는 없으므로 역할명으로 씁니다.
R01–R05 / repetition계획된 비행 반복 번호 (Planned flight repetition)예: G1-V0-R02는 좌우 yaw 차등 카메라 그룹의 최종 평가 경로 두 번째 반복입니다.
G0 · 명목 카메라 구성 · 30회 (약 77%)G1 · 좌우 yaw 차등 구성 · 9회 (약 23%)
그룹경로회수주 역할
명목 카메라 구성 그룹 (G0)P0–P4 개발·교정 경로 + V0 고정 최종 평가 경로각 5회 = 30회개발 경로에서 규칙을 정한 뒤 V0를 평가
좌우 yaw 차등 카메라 구성 그룹 (G1)P0, P4 개발 경로 + V0 고정 최종 평가 경로각 3회 = 9회P0/P4는 사전 지정 확인, V0는 최종 평가

합계는 39회입니다. G1의 P4는 실험 전 정한 대표 S자 경로입니다. “최적 경로”라는 뜻이 아니며, V0 결과를 보고 다른 경로로 바꿀 수 없습니다.

식별과 반복

run_id는 계획된 조건·반복 슬롯이고 attempt_id는 그 슬롯을 실제로 시도한 기록입니다. 예를 들어 기록기가 고장 나 다시 해야 하면 같은 run_id에서 attempt를 늘립니다. 최초 유효 attempt가 본 결과가 되며 모든 실패 attempt도 남깁니다. 각 실행 전 PX4·기체·기록 상태를 초기화하고 manifest의 seed를 요청하되 실제로 어느 난수 모듈에 반영됐는지 확인합니다.

4. 좌표와 카메라 규약

연구 세계좌표와 카메라 좌표

프레임축 순서와 방향주요 혼동 방지
세계 ENU(x,y,z)=(동/오른쪽, 북/전방, 위), 원점은 착륙장 기준점이 연구의 경로 수치와 카메라 위치는 이 프레임입니다.
카메라 광학 RDF(x,y,z)=(오른쪽, 아래, 전방)영상의 광선 좌표이며 ENU의 x/y/z와 축 뜻이 다릅니다.
PX4 LOCAL_NED(north,east,down)ENU와 원점이 다를 수 있습니다. 실제 origin/heading을 읽어 변환합니다.
기체 body FRD(forward,right,down)자세 quaternion과 위치 프레임을 구분해야 합니다.
Gazebo 카메라 자세 quaternionparent/child가 명시된 optical↔world transform, 배열 순서 xyzwposition ENU와 orientation frame·순서를 각각 기록합니다.
PX4 attitude quaternionbody FRD → Earth NED, 배열 순서 wxyz카메라 optical quaternion과 성분만 바꿔 대체할 수 없습니다.

두 카메라의 렌더링 기준 광심은 왼쪽 (−12.5, 0, 0.1)m, 오른쪽 (+12.5, 0, 0.1)m이며 baseline은 25m입니다. 추정기에 넣는 위치는 참 위치가 아니라 별도로 만든/측정한 RTK 광심 관측입니다. 광학 파라미터는 1280×720, 왜곡 없음, fx=fy≈8241.65px, 주점 (640,360), 수평 FOV 약 0.155rad입니다.

p_C = R_WCᵀ · (p_W − C_W)
u = fx · X_C / Z_C + cx
v = fy · Y_C / Z_C + cy

R_WC는 카메라 RDF 벡터를 세계 ENU로 보내는 회전행렬입니다. 카메라의 광축·좌우 라벨·quaternion 순서를 실제 생성된 Gazebo transform과 대조합니다. 설정 텍스트만 보고 회전이 적용됐다고 간주하지 않습니다.

세계 ENU에서 PX4 LOCAL_NED로 위치를 옮길 때

world position p_W = [E, N, U] m
measured local-frame origin o_W = [E₀, N₀, U₀] m
if axes/heading alignment is verified: p_NED = [N−N₀, E−E₀, U₀−U] m
velocity v_NED = [v_N, v_E, −v_U] m/s

이 식은 같은 시뮬레이션 epoch에서 측정한 원점과 축 정렬이 확인된 경우에만 성분 변환으로 쓸 수 있습니다. NED 원점은 configured spawn 값으로 대체하지 않습니다. reset counter와 heading이 바뀌었거나 축이 정렬되지 않으면 해당 frame generation을 다시 관측하고 검증된 회전을 적용합니다. 위치 frame과 자세 frame은 별도 계약입니다. PX4 yaw는 북쪽 기준 방위각을 radian으로 정규화해 사용합니다. 구현은 trajectory_contract.py에 있습니다.

명목 카메라 구성과 좌우 yaw 차등 구성

카메라 구성 그룹왼쪽 광학 yaw오른쪽 광학 yawroll / 명목 고각
명목 방향 (G0)0°0°0° / 20°
좌우 yaw 차등 (G1)+0.5°−0.5°0° / 20°

방위각은 북쪽 +Y에서 동쪽 +X 방향으로 증가합니다. 세 각도의 계약은 다음과 같습니다.

R_WC(φ, θ, ψ) = Rz_world(−ψ) · R_WC_nominal · Rx_optical(θ) · Rz_optical(φ)
φ = optical-forward 축 roll
θ = 기준 고각 20°에 대한 pitch 보정 (총 고각이 아님)
ψ = 세계 방위각
계산 각도: radian / 각도 공분산: radian²

라이브러리의 기본 Euler 순서를 임의로 대신 쓰면 회전 순서와 방향이 바뀔 수 있습니다. 회전행렬과 각도를 같이 기록하고, ENU↔NED 변환은 원점과 heading까지 확인합니다. 배열에서 단순히 성분 순서만 바꾸면 좌표 변환이 되지 않습니다.

5. 비행 경로와 시간 규격

경로는 시간별 참조 위치·속도입니다. 참조점으로 드론을 순간이동하지 않고 PX4 SITL의 동역학으로 따라가야 합니다.

경로형태·횡진폭전방 거리 D역할
P0직선, 세계 ENU 동쪽 E=0400→300m기본 교정 경로
P1활 모양, A=3m400→300m낮은 횡변위
P2활 모양, A=6m400→300m큰 횡변위
P3단일 S자, A=3m400→300m낮은 S자 변위
P4단일 S자, A=6m400→300m큰 S자 변위
최종 평가 경로 (V0)직선, 세계 ENU 동쪽 E=0600→400m고정된 최종 시험 경로
s ∈ [0,1], D = D_start + (D_end − D_start) · s
세계 ENU 위치 [E,N,U] = [E(s), D, D·tan(20°)] m
P0/V0: E(s)=0
P1/P2: E(s)=A·sin²(πs), A=3m / 6m
P3/P4: E(s)=A·sin³(2πs), A=3m / 6m

경로 배열은 세계 ENU 순서 [동쪽 E, 북쪽 N, 위 U]입니다. 이전 수식 표기의 x는 동쪽 성분 E를 뜻하며, 일반 배열의 x/y/z로 다른 프레임에 옮겨 읽지 않습니다.

생성된 V0 참조 파일은 3D 경로 길이 212.8356m, 참조 시간 47.5671s, 50Hz를 기록합니다. 이 시간은 연구구간 reference의 길이·가감속을 반영한 값이며, 진입·복귀 시간이나 실제 조종체의 총 비행시간이 아닙니다.

시간표와 안정화

  • 참조 갱신은 50Hz. 이동 시간은 3D 호길이 기준 5m/s 순항입니다.
  • 시작과 끝에 각각 5초 half-cosine 가속·감속을 적용합니다. 연구 구간(science) 안에 가감속도 포함합니다.
  • 본 구간 진입 전에 5초 연속으로 속도 <0.3m/s, 위치 오차 <0.5m, heading 오차 <3°를 만족해야 합니다. 준비 대기 한도는 120초입니다.
  • 본 구간 종료 뒤 5초 hold와 안전 종료는 별도 phase로 기록합니다. 준비·진입·복귀 구간을 본 구간 RMSE에 섞지 않습니다.
  • body heading 명령은 북쪽 기준 180°입니다. roll/pitch는 PX4 동역학에 맡기고 실제 값도 기록합니다.

seed가 독립성을 보장하지는 않음

manifest의 seed 번호는 요청값입니다. 기존 SWEEP_SEED가 순서만 섞을 수도 있으므로 Gazebo/PX4/센서 잡음 모듈이 그 값을 실제로 받는지 확인하고 모듈별 effective seed를 기록해야 합니다. seed가 먹지 않거나 입력이 반복되면 독립 반복이라고 부르지 않습니다. 같은 원본·GT 시퀀스 중복 여부도 확인합니다.

두 종류의 반복: manifest의 5회(또는 G1의 3회)는 각각 별도 SITL 실행입니다. Monte Carlo 100회는 저장된 비행 자료를 바탕으로 오프라인에서 센서 realization/추정 계산을 반복합니다. 서로 다른 표본 단위입니다.

YAW_ONLY · 비교 기준ψ자세 미지수 2개RPY_IMU와 같은 IMU roll/pitch 측정 평균에 고정. 참값으로 고정하지 않음
YAW_IDEALyaw 진단주 비교 바깥참 roll/pitch·위치 등을 쓸 수 있는 이상 조건. 이상 진단으로 별도 표기

세 자세각은 앞 절의 회전 규약을 따르고, 계산은 radian·공분산은 radian²입니다. 카메라 XYZ는 두 방법 모두 측정 위치에 고정합니다. A/B/C 결과에 회전행렬, 각도, prior 평균/공분산, 공분산·상관관계, rank/조건수, 수렴 상태와 실패 사유를 남깁니다.

정답 정보가 추정기로 새어 들어가지 않게 합니다. 참 카메라 자세와 드론 GT는 synthetic 센서 생성기 또는 평가기가 쓰는 자료입니다. 일반 추정기는 allowlist에 적힌 센서 관측·영상 입력만 받습니다. C에 드론 RTK/GT/명령 경로를 제공하거나 참 yaw를 몰래 고정해 성공시키면 실험 규격을 위반합니다.

IMU sigma=0은 0 공분산을 역행렬에 넣는 조건이 아니라 별도 idealized fixed-angle 진단입니다. 이것을 finite prior를 쓰는 주 RPY_IMU 결과라고 부르지 않습니다. C가 yaw 관측성이 부족해 rank deficient가 되면 실패를 그대로 보고합니다.

전체 데이터와 같은 표본 수 비교

모든 유효 관측을 쓰는 비교와, 시간 구간을 고르게 대표하는 고유 stereo pair 200개 비교를 모두 수행합니다. 200개 미만이면 표본을 복제하거나 run을 버리지 않고 “200 미충족”을 표시합니다. A/B/C·RPY_IMU/YAW_ONLY 비교에는 가능한 한 같은 frame mask와 같은 센서 realization을 전달합니다.

9. 개발 데이터와 최종 평가 데이터를 분리한다

명목 카메라 구성 그룹(G0)의 P0–P4 개발·교정 경로 기록은 교정 규칙을 정하는 데 씁니다. 최종 평가 경로(V0)는 고정된 최종 시험 세트입니다. V0 기록 품질, 카메라 가시성, 파일 무결성은 수집 시 확인할 수 있지만, 위치 RMSE를 열어 본 뒤 알고리즘·파라미터·경로 선정 규칙을 바꾸면 최종시험으로서 독립성이 훼손됩니다.

  1. 개발 데이터와 기하 모델에서 교정 경로 선택 규칙을 만든다.
  2. 알고리즘·초기값 정책·하이퍼파라미터·선택 규칙을 고정하고 해시/버전을 기록한다.
  3. 선택한 교정 경로의 회전행렬과 고정 카메라 RTK 위치로 대응하는 같은 rig·반복의 V0를 평가한다.
  4. V0 영상은 드론 위치 추정 평가에만 쓰고 카메라를 다시 교정하지 않는다.
  5. 정확도·검출 가능성·비행시간/거리·횡이동을 함께 보고한다. 수치 위치 RMSE 합격 기준은 규격에 없으므로 임의로 만들지 않는다.

성공 프레임만의 조건부 오차와 전체 프레임에서 얼마나 추정 가능했는지를 함께 설명합니다. 교정 실패율, 검출률, 유효 측정률, 3D RMSE/P95, 축별 오차, 자세 오차·관측성 진단, flight time/거리/횡이동이 포함됩니다. RPY_IMU가 언제나 YAW_ONLY보다 낫다고 가정하지 않습니다.

39회만으로 전 세계적 최적 경로, 실제 센서 사양의 현실성, 야외·헬리콥터 성능까지 증명하는 것은 아닙니다. 결론의 범위를 SITL·지정 조건으로 한정합니다.
