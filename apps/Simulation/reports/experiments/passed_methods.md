# Contract-Limited Passed Methods

This file lists methods previously classified as final `PASS` or `STRICT_PASS`
by their stated gate. Measurement-quality rows are now interpreted as
`CONTRACT_LIMITED_PASS`: they are valid only under the coordinate/frame contract
used by the synthetic or replay validation, and are not deployment evidence for
real experiments until the real NED/body/camera extrinsic chain is applied and
the method is revalidated. `CONDITIONAL_PASS`, `NEAR_PASS`, `PARTIAL_PASS`,
`FAMILY_LOCAL_PASS`, detector-only audits, and invalid coverage checks are
intentionally excluded.

Current deployment status:

- No measurement-quality EXP in this file is currently accepted as real-world
  deployment PASS without an explicit camera/body extrinsic validation.
- Runtime loader/profile replay PASS rows remain useful as software-path
  evidence, but they do not by themselves validate measurement accuracy under
  an arbitrary real camera mounting.
- EXP results should be preserved as structure/search evidence, not discarded;
  the PASS label is downgraded from deployment-ready evidence to
  contract-limited evidence.

Exploration does not stop when a method enters this file. New EXP runs should
continue searching for lower validation RMSE, stronger target-window coverage,
better runtime feasibility, and broader validation evidence.

Coordinate contract:

- Calibration/evaluation truth may use PX4 local NED `north/east/down`.
- Internal correction profiles use stereo-center RDF `right/down/forward`.
- Public StereoDistance topics use FRD+range `forward/right/down/range`.
- PASS claims must not rely on ambiguous `x/y/z` fields.
- The direct NED-to-RDF alias `rdf_right=east`, `rdf_down=down`,
  `rdf_forward=north` is not accepted as PASS evidence for either real or
  synthetic experiments. Truth used for RDF evaluation must be produced by an
  explicit `T_source_to_stereo_rdf` transform, or by a producer that is already
  in stereo-center RDF and declares that frame contract.
