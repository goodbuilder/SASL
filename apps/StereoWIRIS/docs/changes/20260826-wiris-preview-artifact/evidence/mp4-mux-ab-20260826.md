# MP4 mux A/B

## Failing application sample

Session `20260826_153835_987796434` used `mp4mux fragment-duration=1000`.
Both files opened in ffprobe but strict software decode exited 1. The repeated
invalid NAL length was decimal `1835295092`, hexadecimal `0x6d646174`, or ASCII
`mdat`. MP4 fragment box bytes were being interpreted as H.264 sample data.

## Same-session live tee

One Left RTSP/depay/parse input was teed to two mux branches for 20.118 seconds:

- `/tmp/wiris-mp4-mux-ab.rqqdBF/fragmented.mp4`: 133,915,544 bytes,
  ffprobe emitted `Invalid NAL unit size`, strict full decode exit 1.
- `/tmp/wiris-mp4-mux-ab.rqqdBF/flat.mp4`: 133,910,049 bytes,
  ffprobe clean, strict full decode exit 0.

The encoded input was identical; only `fragment-duration=1000` differed.
`fragment-mode=first-moov-then-finalise` also decoded, but it can extend EOS
finalization for multi-gigabyte files. Plain `mp4mux` was selected because the
application already requires orderly EOS and preserves the spool when video
validation fails.

## Actual application verification

After removing `fragment-duration`, session `20260826_154943_612706709`
finalized both files in about 2.4 seconds:

- Left: 501,460,047 bytes, 71.2922 seconds, H.264 1280x720, strict full decode
  exit 0.
- Right: 429,074,882 bytes, H.264 1280x720, strict full decode exit 0.

The MP4 remains a direct H.264 copy. No decoder/re-encode or camera encoder
setting change was introduced.
