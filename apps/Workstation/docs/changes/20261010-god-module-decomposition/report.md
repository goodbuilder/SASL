# Workstation 갓 모듈 분리 결과

## 판정

**대상 네 갓 모듈의 구조 분리와 소프트웨어 수용 기준 G1–G6 검증을 완료했다.** 최종 전체 회귀 시험은 **2,243개 통과·2개 건너뜀·경고 1개**, 237.52초, 종료 코드 0이다. 중간에 발견된 RTCM 시험의 경쟁 조건과 정리 누락을 보완한 뒤 전체 시험과 세션 종료를 다시 통과했다. 실장비·배포 환경 준비는 아래 제한 사항에 명시한다.

요청 범위는 기존 네 갓 모듈의 책임·상태·자원 분리다. 작업 기준은 `42b16e0`에 이미 적용되어 있던 RCA 수정까지 포함한 소스이며, 해당 수정과 별도 Simulation 작업을 보존했다. [계획](implementation-plan.md), [수용 기준 G1–G6](change-brief.md), [현재 구조](../../ARCHITECTURE.md)를 함께 볼 수 있다.

## 실제로 바뀐 구조

| 기존 파일 | 이전 → 현재 줄 수 | 실제 책임 이동 |
|---|---:|---|
| `standalone_gui.py` | 13,702 → 319 | QWidget 진입점과 조립만 남기고, 11개 기능 객체가 상태·화면 참조·동작을 소유한다. |
| `workspaces.py` | 17,551 → 147 | 19개 화면·공통 구성요소 모듈로 분리했다. 기존 경로는 명시적 재수출만 하며 실제 앱은 화면 소유자를 직접 import한다. |
| `recording_controller.py` | 8,676 → 65 | 기록 세션, 캡처, 필드 투영, native 완료, 기본 저장 승인, 저장·복구·표시를 나눴다. |
| `measurement_view_controller.py` | 6,677 → 631 | 입력 수집·고정, 방식 선택, geometry 해석, 계획, worker 관리, 결과 반영, 표시를 분리했다. |

네 진입 파일의 합은 **46,606 → 1,162줄**이다. 수용 기준에는 상태의 실제 저장 위치, 제한된 의존성 범위, 자원 목록과 개별 소유자 구성이 포함되며, 이를 구조 시험으로 검사한다.

전체 앱 Python은 **166,402 → 176,640줄**로 늘었다. 이 집계는 시험·도구·생성 MAVLink 코드를 제외한다. 도구까지 포함하면 **168,102 → 178,469줄**이다. 증가분에는 명시적 계약, 상태 객체, 호환 연결, 조립 코드가 포함된다. 명시적인 소유권·의존성 구조를 얻는 대신 연결 코드의 양과 관리 비용이 늘었다. [집계 기준과 값](evidence/source-metrics.json)을 보존했다.

### 패널과 화면

- 상태와 위젯 참조를 기능별 소유자에게 옮겼다. 기존 패널 속성은 해당 소유자의 같은 값에 연결되며 복제 저장하지 않는다.
- 기능 간 접근은 필요한 이름만 허용하는 포트로 제한했다. 기본은 읽기 전용이며 다른 소유자 상태를 변경하는 권한은 별도로 선언한다.
- 이동한 QObject 콜백의 GUI 스레드 실행과 위젯 부모 관계를 유지했다. 종료 처리는 패널의 직접 속성 검색에 의존하지 않고 측정·기록 소유자까지 포함한 자원 목록을 사용한다.
- 동적 PX4 탭 참조도 화면 소유자의 레지스트리에 저장한다. 1,027개 직접·리터럴 쓰기와 동적 참조 경로를 점검했다.

### 기록

- 22개 동작 소유자와 9개 상태 그룹으로 책임을 나눴다. 동작에는 필요한 이름만 가진 포트를 전달한다. Qt 어댑터는 부모·실행 문맥 유지를 위해 `qobject_parent`로 패널을 받지만, 이를 범용 상태·명령 접근에 사용하지 않는다.
- native 완료와 기본 저장 승인은 하나의 승인 장부와 잠금을 공유한다. 원래 행 객체, 실행 세대, 행 번호, lease를 함께 보존한다.
- 늦게 도착한 결과, 중복 완료, 재시도와 rollback이 다른 실행의 행으로 섞이지 않도록 기존 계약을 유지했다.

### 측정

- 캡처 시 검출·telemetry·보정·설정·선택된 방식과 인스턴스를 불변 입력으로 고정한다. 기존 우선 방식·fallback·hysteresis 선택은 이 시점에 한 번 실행한다.
- 순수 geometry resolver와 planner는 고정 이후 위젯·현재 설정·실시간 clock을 읽지 않는다. 실행 중 설정을 바꿔도 이미 캡처한 시도의 입력이 달라지지 않는다.
- 계산 worker 수명, 결과 승인·재시도·원래 실행으로의 귀속, 화면 표시를 각각 분리했다. 기존 Stop 동작과 명시적 worker 복구 기능을 보존했다.

## 관찰한 효과와 기대효과

| 항목 | 현재 근거 | 기대효과 |
|---|---|---|
| 수정 범위 파악 | 화면 import DAG, 기능별 상태와 유한 포트 | 해당 기능의 소유자부터 읽고 변경 영향을 추적하기 쉬워진다. |
| 계산 재현성 | 불변 입력, 변경 후 동일 시도 유지, 독립적인 9 m 수치 검증 | 현재 UI 상태가 이미 접수된 계산에 섞이는 오류를 줄인다. |
| 비동기 기록 안전성 | 공유 승인 장부·잠금, 행/세대/lease 보존 시험 | 지연 결과·중복 완료가 잘못된 행에 반영되는 회귀를 발견하기 쉬워진다. |
| 구조 유지 | 개별 import·소유권·쓰기 범위·자원 가시성·순환 금지 시험 | 후속 변경으로 만능 모듈이 다시 커지는 현상을 감지한다. |

실행 속도, 메모리 사용량, 측정 정확도, 장시간 현장 안정성의 개선은 측정하지 않았다. 위 기대효과를 성능 개선이나 실장비 인증으로 해석해서는 안 된다.

## 검증과 한계

최신 시험 결과는 [검증 기록](verification.md)에 명령·중간 실패·수정·재실행 순서로 남겼다. 개별 단계의 시험 수는 서로 겹치므로 합산하지 않는다.

| 수용 항목 | 최종 판정과 근거 |
|---|---|
| G1 화면 분리 | PASS — 19개 모듈 독립 import·DAG·호환 동일성 및 화면 회귀 |
| G2 패널 소유권 | PASS — 11개 기능 소유자, 쓰기 범위·상태 동일성·Qt 실행 문맥·자원 목록 |
| G3 기록 분리 | PASS — 상태 그룹·공유 승인 장부·잠금·원래 행/세대/lease·지연 완료 |
| G4 측정 분리 | PASS — 고정 입력·선택 방식 유지·순수 resolver/planner·독립 수치 기준 |
| G5 동작과 계약 | PASS — Run/Stop/저장/복구, 좌표·스키마 및 화면 보존 회귀 |
| G6 통합 검증 | PASS — 최종 2,243개 통과, 경로/저장소/타입 선언/공백 검사 통과 |

최종 실행 원문은 [final-regression.log](evidence/final-regression.log), 검증한 429개 소스의 해시와 환경 제한은 [final-acceptance.json](evidence/final-acceptance.json)에 있다. 시험 완료 후 소스 해시가 그대로인지 확인했다.

- 화면 비교: Overview·Camera·Measurement·Calibration·Advanced는 픽셀 단위로 동일하다. Data의 차이는 임시 저장 경로 표시 부분 2,089픽셀뿐이며 직접 비교했다. 기존 좁은 창의 잘림은 이번 작업에서 개선하지 않았다.
- 실제 패널·백엔드·화면을 사용하는 offscreen 캡처에서 예상 밖 콜백 오류는 0건이고 종료 보고의 활성 자원 목록은 비어 있었다. 소유권 inventory 자체의 핸들·맵이 전부 삭제된다는 의미는 아니다. OpenGL 표시 제한은 별도로 기록했으며 3D 렌더링 통과로 계산하지 않았다.
- 초기 시험에서 가짜 WIRIS worker 대체가 누락되어 실제 기본 카메라 주소로 연결을 시도한 사례가 있었다. 성공 응답은 관찰되지 않았지만 장치 수신 여부를 단정할 수 없다. 이후 모든 시험은 loopback만 있는 네트워크 namespace와 외부 연결 시도 실패 장치 안에서 수행했다.
- 정식 `run.sh --check`는 기존 저장소 루트 `.venv` 부재로 실패한다. 시험은 시스템 Python으로 실행했으며 NumPy/SciPy 호환 범위 경고가 남는다. 배포 환경 준비까지 완료됐다는 뜻이 아니다.
- 명시적 호환 API와 일부 큰 단일 화면/기능 모듈은 남는다. 예를 들어 calibration 화면은 4,136줄, camera 기능은 3,778줄이다. 이처럼 남은 큰 기능 모듈은 후속 유지보수 대상이다. 호환 계층 제거 조건은 [compatibility-exit.md](compatibility-exit.md)에 명시했다.
- 변경은 아직 commit/push하지 않았다. 새 소스·시험·도구·문서는 저장소 안에 있으며 다른 PC에서 재현하려면 함께 포함해야 한다. 임시 비교용 소스 복사본은 앱 실행의 의존성이 아니다.

## 좌표 계약

NED `[north,east,down]`, body FRD→NED quaternion `wxyz`, 광학 RDF `[right,down,forward]`, `X_right = R X_left + T`, `C = -RᵀT`, 공개 optical baseline-center FRD와 별도 GNSS midpoint를 유지했다. 왼쪽 카메라 원점의 RDF 증거를 중심점 좌표로 덮어쓰지 않는다. WGS84 각도·고도 기준과 clock 출처도 유지했다.

독립 기준값 `900 px × 0.4 m ÷ 40 px = 9 m`, 왼쪽 RDF `(0.2, 0, 9)` → 중심 FRD `(9, 0, 0)` 및 기존 좌표·스키마 회귀 시험으로 확인한다.

Coordinate contract checked: measurement frozen inputs/resolver/planner, recording schema/rows, workspace labels; NED·body FRD·optical RDF·baseline-center FRD and shared geometry regressions.
