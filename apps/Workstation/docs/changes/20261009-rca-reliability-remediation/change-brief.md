# Workstation RCA 수정

요청: 발견된 문제를 정리하고 안전한 계획, 수정 전후 변경점과 기대효과를 기록한 뒤 실제 수정과 검증을 수행한다.

| ID | 발견된 문제 | 수정 후 기대효과 | 수용 증거 |
|---|---|---|---|
| R1 | frozen pair/request/outcome의 중첩 데이터가 변경 가능 | 생성 이후 원본·반환값 변경에도 내용/해시 고정 | 외부 별칭 변경, 직접 변경 거부, 독립 canonical JSON/hash, spawn/재현 시험 |
| R2 | CI가 삭제된 test_workstation.py 참조 | 현재 Workstation 전체 회귀를 자동 수집/실행 | CI 경로 검사, 실제 전체 수집과 테스트 |
| R3 | 과거 경로 기록과 이식성 검사 분류 불일치 | 불변 과거 기록 보존과 활성 경로 검사 동시 유지 | 내용 해시로 제한된 기록 분류, 새/변경 경로 거부, 저장소 gate |
| R4 | Run 상태가 UI panel의 공유 필드에 존재 | Qt 독립 Run 소유자가 전이를 결정하고 UI는 투영 | headless 상태 시험, 저장 실패/늦은 종료/반복 측정, 경계 검사 |
| R5 | 시작된 worker의 장기 실행 상태/선택적 복구 부재 | 실행 경과를 보고 선택한 worker만 명시적으로 재시작 | 무응답 작업→실패 증거→새 작업 성공, 동료 method 유지, GUI 비차단 |
| R6 | README의 MAG 시작 조건/방법 수 등 충돌 | 현재 계약과 과거 이력이 명확하게 구분 | 생산 코드/회귀와 문서 대조 |
| R7 | 수정 효과와 회귀 근거 필요 | 정상 흐름·오류 흐름·패키징 검증 결과 추적 | verification.md의 명령/결과/환경, 최종 변경 검사 |

수정은 Workstation와 직접 관련된 공통 품질 검사에 한정한다. 사용자 소유 Simulation 변경을 보존한다. 전체 UI 재설계/수학 교체/하드웨어 설정 변경은 요청된 결함 수정에 필요하지 않다. R4의 구조 수용 기준은 측정 Run의 독립 소유권이며 전체 UI 파일 크기 감소를 완료 기준으로 가장하지 않는다.
