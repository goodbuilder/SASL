# Impact Analysis

## Preserved invariants

- Raw P1/P2/Drone rows remain independent and unchanged.
- `gnss_baseline_center_local_level_frd` stays separate from camera `baseline_center_frd`.
- JSONL is authoritative; XLSX is replaceable derived output.
- Recording/store failure never gates Telemetry, Measurement, media or the next run.
- One data-store writer remains the sole file owner.

## Affected layers and components

| Layer | Change |
|---|---|
| Stream registry | add bulk key/path |
| Recording controller | build/append one derived row on primary Drone callback |
| Sensor handoff | invoke explicit recording-owner method after raw Drone row |
| Latest XLSX | fixed sheet spec and generation discovery |
| Data status | automatic stream projection; no widget code expected |
| Schema/docs/tests | JSONL fields, source/clock contracts, regression fixtures |

## Feature dependency, ownership, and coupling changes

Dependency: Sensor presentation -> public Recording controller method -> pure GNSS estimator ->
DataStorageController/store. Sensor owns no file, Recording owns record construction/admission, the
store remains sole writer, and Latest XLSX remains a read-only derived consumer. No widget/private
state access is added.

## Worker CPU/GPU resource impact

No new worker/queue/process/GPU work. One O(1) calculation and JSON encoding/append attempt per
primary Drone GNSS callback uses the existing bulk queue/writer. At 5-10 Hz and a <=4 KiB accepted
row budget, incremental worst-case planning volume is about 72-144 MiB/hour. Existing bulk
oldest-drop policy is preserved; overload must remain visible in per-stream dropped counts.

## Compatibility and migration

Additive JSONL file, stream key and XLSX sheet. No historical backfill. Existing workbook schema
marker stays v1 so an app-owned workbook can be atomically refreshed; new generation rows mark it
stale. Older readers may ignore the new file/sheet. Legacy session Parquet/review output is excluded.

## Rollback and recovery

Code rollback stops new rows/sheet generation; existing JSONL remains valid evidence and is never
deleted. XLSX can be regenerated by the old version without the extra sheet. No settings/device
rollback.

## Risks and assumptions

- Additional bulk pressure can evict the oldest bulk record during sustained overload.
- Latest selected P1/P2 samples may be up to the approved 1000 ms apart; row stores exact clocks.
- Primary Drone GPS is the sole trigger; GPS2 remains raw evidence only.
- A WAITING row may contain partial source evidence but null geometry.
- One source row is self-contained and duplicates some raw GNSS values by design for reproducibility.
- Manual-record rows have no Measurement generation and therefore do not enter latest-Measurement
  XLSX, consistent with existing workbook scope.
