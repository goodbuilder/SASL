# StereoDistance 작업 지침

이 문서는 `/home/moontaehyung/영상감시시스템/apps/StereoDistance` 아래에서 작업하는 코딩 에이전트가 따라야 하는 프로젝트 전용 규칙이다.

## 기본 원칙

- 명확하고 되돌릴 수 있는 작업은 스스로 끝까지 진행한다.
- 삭제, 초기화, 외부 배포, 권한 상승, 데이터 손실 가능성이 있는 작업은 사용자 확인 없이 진행하지 않는다.
- 기존 코드 구조와 패턴을 먼저 확인하고, 변경 범위는 작게 유지한다.
- 사용자가 만든 변경은 임의로 되돌리지 않는다.
- 파일 검색은 우선 `rg` 또는 `rg --files`를 사용한다.
- 코드 변경 후에는 가능한 범위에서 테스트, lint, typecheck, smoke check 중 적절한 검증을 수행한다.
- 검증하지 못한 부분은 최종 보고에 명확히 남긴다.

## 프로젝트 문서 역할

- `docs/usage.md`: 설치, 실행, 빠른 사용법, 주요 기능 안내.
- `PROJECT.md`: 프로젝트 목적, 시스템 구조, 핵심 워크플로, 측정 흐름, 분리 계획.
- `DESIGN.md`: UI/스타일 방향과 디자인 토큰.
- `DESIGN-ibm.md`: IBM/Carbon 계열 원본 디자인 레퍼런스.
- `../UPDATE.md`: 의미 있는 변경 이력과 인수인계 로그.
- `AGENTS.md`: 에이전트가 따라야 하는 작업 규칙.
- `README.md`: 문서 목차.

## 디자인 기준

- 현재 UI는 현장 운용 대시보드 성격을 우선한다.
- 디자인 문서는 시각적 영감으로 사용하되, 카메라/YOLO/Pixhawk/RTK 상태를 빠르게 파악할 수 있는 밀도와 가독성을 우선한다.
- Apple식 마케팅/갤러리 레이아웃보다 IBM/Carbon 계열의 구조적이고 차분한 운용 UI가 이 프로젝트에 더 적합하다.
- 화면 작업 시 다음을 우선한다.
  - 명확한 상태 계층
  - 낮은 시각적 소음
  - 일관된 버튼, 입력, 상태칩
  - 장비 운용자가 빠르게 스캔할 수 있는 정보 밀도

## 업데이트 기록 규칙

기능, 구조, 디자인, 문서, 테스트, 설정이 의미 있게 변경되면 `UPDATE.md`에 한글로 변경 기록을 추가한다.

`UPDATE.md`는 작업 맥락을 파악하기 위해 매번 읽는 필수 문서가 아니다. 단, 새 기록을 작성할 때는 최신 버전 번호만 확인하고 다음 버전을 계산한다.

버전은 `v대변화.소변화.수정` 형식을 사용한다.

- 대변화: 주요 구조 변경, 화면 흐름 대개편, 호환성에 영향이 큰 변경.
- 소변화: 기능 추가, UI 개선, 문서 체계 변경, 내부 구조 개선.
- 수정: 버그 수정, 디버깅, 오타 수정, 테스트 보강, 작은 스타일 정리.

기록은 최신 항목을 위에 추가한다.

기록 형식:

```md
## v1.0.0 — YYYY-MM-DD — 변경 요약

- 변경:
  - 변경된 내용을 적는다.
- 이유:
  - 왜 변경했는지 적는다.
- 확인:
  - 어떤 방식으로 확인했는지 적는다.
- 남은 위험:
  - 아직 남은 위험이나 미완료 사항을 적는다.
```
